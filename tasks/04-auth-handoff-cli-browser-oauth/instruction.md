Add browser based Google/GitHub sign-in next to the current email/password auth. A new gamepigeon auth oauth google or gamepigeon auth oauth github command opens the browser at the auth worker, which rejects any other provider, checks that provider's credentials are configured, then redirects onward. On macOS route the link the way the desktop overlay already routes Arc/Dia links, a real tab via AppleScript, instead of a plain OS open. The CLI listens on 127.0.0.1:3210, falling back to a free port if busy, answers /auth/ping, and turns /auth/callback?token=... (tolerating a redirect that glues token onto an existing state param) into a saved session and a small HTML page, with an escaped reason shown on error or cancellation. The worker's GET /cli/oauth and GET /cli/handoff must each refuse a next target that isn't a plain http 127.0.0.1 or localhost URL before attaching a token. /cli/handoff hands the signed-in browser session back to that address, keeping its query, via an uncached self redirecting page, answering 401 with guidance when there's no session. From the CLI auth module export startOAuthCallbackServer(port), arcTabScript(bundleId, url) and isArcBundle(bundleId) so tests can drive the listener and Arc handling directly, following the exact shapes, trust rules, and cookie/error-page conventions pinned down in docs/oauth-handoff-contract.md.
