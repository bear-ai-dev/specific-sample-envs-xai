On 2026-09-09 `contracts/fixtures/restaurant-arena-trace-v3.json` was regenerated by `bun scripts/export-arena-trace.ts`. Every recorded checkpoint `stateHash` in the checked-in fixture was stale while every `restaurantStateHash` still matched; probing showed the old hashes were computed before `verifiedOrderIds` joined `checkpointState()`. The action sequence, `startTime` and key order were reproduced byte-for-byte, so only the hash values changed.

**Why:** it proves the mismatch was engine drift, not a capture bug, so native replay was kept strict instead of loosened to accept the old hashes.

**How to apply:** if `bun run check:trace-fixture` reports the fixture stale after an engine change that alters `checkpointState()`, regenerate deliberately and confirm the rest of the export is unchanged. Note `docs/evidence/issue-275/played-shift.json` can never replay under today's engine (different worker array order plus pre-drift hashes) — don't treat it as a passing target.
